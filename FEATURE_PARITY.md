# BOOP / NOOP feature parity audit

Audit date: 2026-10-01. Reference: `reference/noop`, commit `7f396e98ed9d259df08e3a0a58cfac05fc70615c`. This is a source audit, not a claim that Windows implementations or hardware actions have been tested. Reference files remain untouched. Source paths below are relative to `reference/noop` unless marked BOOP.

## Authority and acceptance rule

The actual navigation authorities are `Strand/App/RootView.swift` (30 macOS destinations), `Strand/App/TabRoute.swift` (nested metric/full-day/hydration/coupled routes), and `android/app/src/main/java/com/noop/ui/AppRoot.kt` (shipped Compose destinations and their implementations). Comments calling routes placeholders are stale where the route invokes a real screen. Reachable controls and their backing engines, rather than roadmap prose alone, define this inventory.

Implement every applicable local BOOP capability. Other-hardware features remain explicitly classified; platform APIs need Windows equivalents or file-import routes. Never present an empty screen, fabricated sensor value, generic substitute formula, or untested strap write as completed parity. Analytics require reference fixtures/oracles and explicit data sufficiency. This inventory covers feature-level behavior; visual identity is not the acceptance criterion.

BOOP baseline at audit start: native Bleak connection/reconnection, BOOP CRC framing, live HR and available RR/RMSSD, battery/firmware/clock, durable history sync with cancellation and raw packets, chart windows/day summaries, readings CSV, SQLite snapshot, localhost UI and Windows launcher. Sources: BOOP `boop.py`, `whoop_protocol.py`, `storage.py`, `web/app.js`, `web/index.html`. Existing SQLite has frames/readings/chunks only; it is not NOOP's schema or `.noopbak` format. Retain raw originals and unknown/invalid device timestamps.

Status below: **partial** means a baseline implementation exists but lacks listed behavior; **gap** means absent at audit start; **conditional** means requires sensors, user input, another device, OS integration or credentials; **experimental** means preserve the explicit opt-in and limitations. P0 = foundations; P1 = everyday BOOP parity; P2 = full local feature breadth; P3 = optional integration / hardware / experimental work.

## Implementation sequence and coherent pages

1. **Foundation first:** additive database migrations, local timezone/day ownership, source provenance and safe import/exposure limits. Pure analytics module uses reference-derived fixtures (Swift/Kotlin oracle where available); preserve unavailable/confidence reasons in every API. Existing raw collection and durable-before-ACK sync must survive unchanged.
2. **Daily BOOP:** Today, Sleep, Activity and Health. Shared computed daily model powers every card/detail/report; user edits are persistent inputs with an explicit recompute path. Never separately recalculate inconsistent numbers in JS.
3. **Full local breadth:** Insights (Intelligence / Explore / Compare / Trends / Journal / Experiments), Activity (Workouts / Lifts), Health (Stress / Vitals / Hydration / Lab Book / Cycle / Rhythm), Tools (HRV / Breathing / Intervals / Sessions). Add exports and imports with fixtures and round trips.
4. **Device and data management:** Device (Connection / Alarms / Power saving / Automations / Diagnostics); Data (Imports / Source fusion / Exports / Backup / Storage). Every command is named, schema-checked, allowlisted and gated on device family; no generic hexadecimal sender.
5. **Optional integrations:** Settings (Profile / Units / Appearance / Features / Advanced / Integrations / Help). Credential/OS/hardware-dependent entries state what is required; build adapter/configuration and tests without contacting external services or sending user health data.

Recommended endpoint conventions: GET reads; POST starts actions or creates; PATCH edits; DELETE removes with UI confirmation. IDs must select actual stored records, not device address guesses. API shapes should include `available`, `reason`, `source`, `confidence`, and coverage alongside computed values. File uploads need bounded size, ZIP traversal/bomb protection and transactional/idempotent writes. Reports are generated locally.

## Verification and remaining acceptance work

The audit performed no Bluetooth actions and sent no user data externally. The original matrix is frozen at audit start; the closure below records subsequent implementations. Device writes, Windows sleep/wake guarantees, native `.noopbak` interoperability, experimental physiology and OS notification delivery remain separate validation gates. The macOS notification watcher is explicitly unshipped; BOOP has no measured BLE steps or MG ECG; those must not inflate a claim of missing supported functions.

## Implementation closure — 2026-10-01

**Implemented** below means local code and its API contract exist, with the named automated test evidence. It does not mean the strap actuator, Windows notification delivery, every imported file variant, or every UI flow has been physically verified. Browser acceptance is recorded by the integration owner separately. No blanket 100% parity claim is made.

Scope is the applicable local BOOP/Windows counterpart of reachable NOOP functionality at the pinned revision. The initial priority/status tables above remain an **original audit**, not a current unresolved-gap list. The full regression run completed **284 tests: 283 passed / 1 skipped**; the skip is Windows symlink-creation privilege. Python compilation and JavaScript syntax checks passed. Backup & Sync has 11 focused service tests and expanded restore regressions, with API/lifecycle and interactive browser checks. Named tests below supply source vectors and domain/security regression evidence, including Coach context/model-refresh/day-rollover. Required examples are bundled under `vendor/noop/test-fixtures/` with upstream provenance and hashes. Hardware and native-platform exclusions remain explicit.

Live stress check-in state and dismissal use `/api/automations/checkin`; the master/check-in/haptic opt-ins use `/api/automations`. Coach question/provider selection uses `/api/coach`, alongside the history and brief routes below. These are local endpoints, not external data services.

Coach `/api/coach/models` is an explicit provider GET metadata/authentication-only refresh with no health/conversation payload: at most 200 model IDs, a 1 MB response, a 15-second request and no redirects. The source's strictly-forward day rule uses the actual profile timezone: a new day clears inference context without deleting the bounded readable transcript; failed requests do not advance the successful context marker or alter saved messages. These paths are included in the final regression run.

Verification is separated by evidence type: automated tests use temporary data/simulated devices. ### Explicit exclusions and remaining limits

- **Hardware pending:** none of the newly ported controls was executed on the owned strap during implementation. Alarm readback matching, actual vibration, reboot sensor-light behavior, HR broadcast advertising and newly probed firmware replies need a distinct user-authorized physical check. A successful BLE write or dropped link is not that proof.
- **Windows adaptations:** tray/startup/local notifications and file imports replace applicable desktop flows. Native HealthKit/Health Connect permissions, phone alarms while the device sleeps, phone widgets/live activities, Watch/Siri actions and mobile notification listeners are platform-specific, not fake Windows controls.
- **Other devices / credentials:** MG ECG, 5/MG measured steps/deep collector, Oura feature probes/compile-gated OAuth history and Polar pairing require their own hardware or credentials. Their absence is not an owned-BOOP local sensor gap. Android self-hosted push is an optional configured external transport; no endpoint/token was supplied or transmission enabled here.
- **Wake refinement:** `sleep_refinement.py` ports `WakeMotionRefinement` with literal synthetic fixtures in `tests/test_sleep_refinement.py` (9 passing tests). Both whole-window streams require 80% dense minutes (at least 2 gravity / 1 actual step sample per minute); eligible wake lasts at least 5 minutes, has no source-defined locomotion, and has at least 80% posture-stable minutes. Burst minutes retain wake with one-minute padding. The default-off setting and analytics path are wired; totals and efficiency use refined segments. Absent real BOOP step samples preserves original segments exactly.
- **Optional native breadth not claimed complete:** additional native layout preferences and native update/language/avatar surfaces remain separately classified. Both default V2 and independent V1 staging are implemented and selectable. V1 has 15 focused source-fixture tests; no Swift/Kotlin compiler oracle was available, so floating-point bit identity is not claimed. Scheduled diagnostic exports and Coach streaming are implemented locally. The read-only source audit found no shipped chart-attachment composer; the Gemini helper and inert toggle do not establish a reachable required vision flow. BOOP's explicit text Gemini adapter is an available counterpart, not a claim that source-native vision was ported. No source evidence supports a mandatory stage-triggered early-wake algorithm or a shipped pre-sleep HR feedback flow; `PreSleepHeartRateFeedback` is only a library helper at this pinned revision.
